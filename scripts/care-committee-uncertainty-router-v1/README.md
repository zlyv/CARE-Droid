# CARE-Droid Diverse Classifier Committee Uncertainty Router v1

This package changes **only the Stage-II routing decision**. The official
Stage-I probability remains the already-frozen Global24 L2 logistic-regression
probability, and every routed APK uses the same frozen
`CARE/RGCondAttn/Dedup/BoundedCorrection` expert. The committee mean is never
used as the Stage-I probability.

## Committee and scores

The four fixed members are Logistic Regression, Random Forest, XGBoost, and an
RBF SVM. Every member receives the exact same 24 Global24 columns produced by
the established fold-safe loader. LR and SVM apply model-internal scaling fit
only on their training rows; the underlying Global24 extraction, columns, and
fold-safe source preprocessing are unchanged. RF and XGBoost consume that same
matrix directly.

Each member is calibrated with a Platt/sigmoid calibrator. For an outer 2017
fold, raw scores for calibration are generated by an inner stratified OOF pass
over `outer_train`; the calibrator is fit on those train-only OOF scores. The
member is then refit on all `outer_train` and predicts the untouched
`outer_validation`. The fit function has no validation-label argument.

For calibrated member probabilities `p_m`:

```text
p_bar = mean_m p_m
U_PE  = H(p_bar)
U_MI  = H(p_bar) - mean_m H(p_m)
```

`A25`, `Committee_PE25`, and `Committee_MI25` each route an exact 25% within
the established source outer fold. Future diagnostics route an exact 25%
independently within 2018, 2019, 2020, and 2021. The count convention is the
same `round(0.25*n)` convention used by the existing project implementation.

## Leakage controls

- 2017 uses the existing fixed 799-APK, five-fold manifest.
- Each source outer validation fold is absent from member training and Platt
  calibration.
- Future members and calibrators use all 2017 source data only.
- The future runner constructs member probabilities, committee scores, routes,
  and final probabilities before its executable label gate permits future
  labels to be read.
- Future results are diagnostics only and must not be used to select members,
  hyperparameters, calibration, score formulas, or budget.

## Dependencies

The package does not install or upgrade anything. It requires the existing
project environment with NumPy, scikit-learn, XGBoost, and PyTorch (PyTorch is
needed when the reused CARE loader is imported). The server script first checks
`/home/boyuanjie/venvs/malscan/bin/python`, which is the interpreter used by the
completed full MalScan experiment. It then checks other existing project
interpreters and accepts an explicit `PYTHON_BIN`. An interpreter is selected
only if all four dependencies import successfully. CPU execution is the fixed
default for reproducibility; CUDA is not required for these lightweight
members.

## Run

From the `tasa-droid` repository root:

```bash
unzip -o care-committee-uncertainty-router-v1.zip -d scripts/
mkdir -p artifacts
bash scripts/care-committee-uncertainty-router-v1/run_on_server.sh \
  2>&1 | tee artifacts/care-committee-uncertainty-router-v1.console.log
```

To use another interpreter:

```bash
PYTHON_BIN=/path/to/python \
bash scripts/care-committee-uncertainty-router-v1/run_on_server.sh
```

The primary comparison is `A25` versus `Committee_MI25`; predictive entropy is
secondary. Metrics include error recall, high-confidence error recall,
accepted risk, Repairable Error Recall, Harmful Capture, Unrepairable Capture,
BA, AUC, F1, fixed, broken, and net.

This package intentionally does **not** include a direct Stage-II classifier.
That would change the downstream decision rule and confound the router-only
comparison; it should be a separate controlled ablation if later requested.

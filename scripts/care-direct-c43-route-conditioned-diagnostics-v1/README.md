# Frozen route-weighting diagnostics after source NOT_SUPPORTED

This package is explicitly authorized to run two diagnostics despite the failed source gate. The 2017 conclusion remains `ROUTE_CONDITIONED_TRAINING_NOT_SUPPORTED`; future or within-year performance cannot select a weight, threshold, seed, architecture or formal mainline. No new static feature is extracted.

The four arms are the completed source B0/B1/B2/B3: equal BCE, nested route 4:1 weighted BCE, matched class weight mass, and class/prediction-side/Host-tertile conditional weight permutation. Actual source-v2 implementation files are verified against the completed implementation manifest and reused read-only, with absolute family-module loading retained. Every new file is confined to this independent script/output pair.

Frozen diagnostic: all 799 training APKs are from 2017, with the historical DIAGNOSTIC_SPLIT_SEED and model seeds 900000/900001/900002. The source-only B0 internal early stopping determines epoch counts. B1/B2/B3 reuse these counts and the same preprocessing/capacity. No target label enters a fit. Training route is regenerated by 4-fold crossfitting with 3-fold member calibration, ranked Top25% within each held-out cohort. The full-source shuffle seed is the already-fixed source seed 20261017. All four arms predict the same 1989 APKs and use the frozen year-wise deployment routes. Historical frozen B0 probabilities must replay within 1e-4 with all decisions equal before weighted fits.

Within-year diagnostic: independently retrain each year (793/399/397/400 APKs) using existing fixed five folds. Only that outer fold's training labels, backgrounds, prototypes, scaler and crossfitted routing weights enter its models. The existing Stage-I checkpoints are reused when compatible, or the existing classifier code refits within the same fold without writing formal caches. B0 Direct-C43 is retrained for each fold; B1/B2/B3 reuse its training-only early-stop epoch counts. The conditional-shuffle seed remains 20261017+fold, exactly the source-fold rule. This is in-year adaptation, not temporal generalization. These Direct within-year baselines are newly evaluated, not mislabeled reused bounded predictions.

The existing frozen runner and family within runner are reused through callbacks that fit all four matched arms. Their output/checkpoint destinations are redirected to this independent directory. No old result or formal cache is overwritten, and no APK is installed, run, rewritten or parsed. Twenty within-year contexts plus one frozen context are expected. Each context retains every training APK. Exact source/test SHA overlap blocks the temporal diagnostic; no silent exclusions are applied.

Reports provide each year and pooled/macro-year summaries of Stage-I and Stage-II BA, ordinary accuracy, AUC, F1, percentage-point gains, fixed/broken/net, FN/FP decompositions, routed coverage and both conditional AUCs. Same-year fold tables and matched paired uncertainty intervals are also exported. Macro-year metrics weight years equally; pooled metrics weight APKs. Intervals are exploratory, unadjusted and conditional on fitted models; they do not account for app-family dependence, refitting variation or the prior research sequence. No diagnostic ranking promotes a model.

The frozen summary is written before within-year training, so `frozen_future_metrics.csv` can be viewed while the remaining folds run. Sealed frozen labels are parsed by the summary only after all four frozen predictions exist. The legacy feature CSV contains metadata labels; the frozen model fits receive only source labels. The separate within-year label tables are inspected for identity/folds and for their expressly authorized OOF evaluation.

Server dependencies include the completed `care-direct-c43-route-conditioned-training-v2`, classifier-family Stage-II scripts, historical Direct future scripts and results, and existing full-year cached assets. Missing inputs fail closed rather than trigger feature rebuilding. The before/after manifests protect listed reused files, not the whole project. A fresh output directory is required; failures preserve partial tables and write BLOCKED. There is no automatic resume or post-diagnostic experiment.
